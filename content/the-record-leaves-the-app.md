[Prudence](https://codeafridi.github.io/Prudence/) is a small tool for writing down decisions: the question, the options, what you picked, why, and what would make you flip. It runs in the browser and stores everything locally. That is the right default for something you might not want on a server.

But a decision record has a second life. It gets sent to a colleague, attached to a postmortem, printed for a review, filed next to a contract. A page that needs an app to open is not a record yet. It is a note that happens to have structure.

So the export writes one HTML file. No scripts, no network, no install. Open it in five years on a machine that has never heard of Prudence and it still looks like the same document.

## Why HTML and not a PDF library

A PDF is the obvious answer and the wrong first step. Generating one in the browser means a large dependency, a font pipeline, and a layout engine that knows nothing about the page. The browser already has all three.

The file carries `@page` rules for A4, `break-inside: avoid` on entries, and a print stylesheet that drops the screen chrome. The "Print / save as PDF" control calls `window.print()`. Every browser turns that into a PDF, and the result is the same layout the reader sees, because it *is* the layout.

If PDFs ever need to be generated on a server, the same HTML can be fed to a headless browser. The export format stays the source of truth.

## The fonts have to come along

The whole point of the design is the pairing: a serif for the record, a monospace for labels, clause numbers, and dates. Falling back to Georgia on someone else's machine would turn a typeset page into a web page that lost its stylesheet.

So the export fetches the four woff2 files from the same origin, base64-encodes them, and writes them into the document as data URLs. About 300 KB, all inlined, all offline:

```js
@font-face {
  font-family: "Newsreader";
  font-style: normal;
  font-weight: 400 600;
  src: url(data:font/woff2;base64,...) format("woff2");
}
```

The first version of the exporter linked to `/fonts/...` and looked correct in testing because the test opened the file next to the app. That is the trap with self-contained output: it works until it leaves the room.

## The form is the content

Two details changed the page more than any CSS:

**Clause numbers are derived, not copied.** The app numbers entries `1`, `1.1`, `1.2.1` from the tree every time it renders. The export runs the same function rather than trusting anything stored, so a branch that was re-parented yesterday cannot leave stale numbering in a document that gets signed today.

**A branch that was not taken is part of the record.** In the app, the abandoned branch is dimmed. In print, dimming alone reads like a printing error, so the export labels it: *Under "yes (managed multi-region)" · Branch not taken*. The roads you didn't take are half the value of a decision log.

## What the page does not do

It does not try to be a report. There is no chart, no summary paragraph generated by a model, no dashboard. It is the record, printed. If you want an analysis, that is a different document, and it should say so at the top.

The other thing it does not do is require the app to exist forever. The file is the artifact. Prudence can change its schema, redesign the canvas, or disappear; the page someone put in a folder in 2026 still opens, still reads, still has the dates.
